# Atlas 源码构建设计

用户已选择：没有原始源码，以当前页面为依据重建，尽量保留现有功能；删除 dist 后仍可完整构建、正常运行。

## 方案

仅迁移压缩资源可以恢复 dist，但不能提供可维护源码，已排除。采用用户选择的源码重建方案：从现有页面梳理应用算法，恢复为独立 ES 模块，替换内嵌第三方库为固定版本 npm 依赖。保留现有 HTML、样式及交互；模型与纹理是原始输入素材，无需从代码生成。

## 架构与约束

- Node.js 22.12+；pnpm 管理依赖并锁定版本。
- 根 index.html、src/ 为应用源码；public/ 放地图样式、模型和纹理，均纳入版本管理。
- Vite 构建页面、样式及几何 Worker 到 dist；build.mjs 再生成本地服务入口；Cloudflare 准备脚本只消费生成物。
- MapLibre 5.24.1、Three.js 0.187.0 尽量与现有 bundle 一致。几何三角化、裁剪、矢量瓦片及骨架算法使用包管理器依赖。
- 保留城市导航、搜索、俯仰、日照、建筑、植被、道路、路灯、车辆、船舶、列车、阴影、动画、建筑档案及移动端适配。
- 恢复模块与有意义的导出名称，算法中的局部变量逐步整理；不声称恢复了上游原始源码或原始建模工程。
- 构建不下载原站资源。运行时地图、搜索及瓦片仍依赖已有在线服务。
- start、build、test、deploy 在没有 dist/cloudflare 时均通过完整构建生成所需输出。部署仅验证准备流程，不发布。

## 验收

在临时目录仅复制受版本管理的源码和素材，排除 dist/cloudflare，使用已安装依赖完成构建；检查页面入口、Worker、模型、纹理、本地路由及 Cloudflare 路由。单元测试覆盖场景二进制、几何构建及交互行为；浏览器验证渲染与控制功能。外部数据服务失败与源码构建失败分开报告。
