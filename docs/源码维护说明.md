# 源码维护说明

## 从入口定位问题

- `src/AtlasApp.js`：页面事件、城市导航、搜索取消、显示设置和建筑档案。
- `src/map/TileScheduler.js`：街区瓦片请求、植被缓存、Worker 并发、结果版本校验和分帧上传。
- `src/workers/geometry.worker.js`、`src/geometry/SceneAssembler.js`：解码输入、组合几何结果及转移二进制缓冲区。
- `src/geometry/BuildingGeometry.js`：OSM 标签规范化、建筑部件归属、各类屋顶与墙体生成。
- `src/geometry/LandscapeGeometry.js`：道路宽度、路缘、植被、路灯和地表拓扑。
- `src/geometry/TileClipping.js`、`MeshPacking.js`：瓦片边界裁剪、顶点索引化及建筑拾取范围。
- `src/scene/MapScene.js`：地图与 Three.js 的坐标和 WebGL 状态衔接、瓦片上传、显示开关及拾取。
- `src/scene/` 和 `src/routes/`：实例化、植被 LOD、入场动画及车辆、船舶、列车的路线与时钟。
- `src/models/SceneCodec.js`：模型二进制目录、TypedArray 类型、对齐和边界校验。

## 命名和注释

局部变量描述角色，例如 `tileX`、`ringIndex`、`roadWidth`、`projectedFraction`、`nearestRoad`。避免恢复压缩代码时遗留的字母名和 `value1` 等无语义替代名。常规接口名称 `gl`、`id` 可保留。

注释解释约束、单位和处理顺序，例如为什么需要经度回绕、为什么先生成建筑部件，以及缓存何时失效。公式和循环本身已经清晰时，不逐行翻译代码。

对象属性 `x/y/z`、Clipper 的 `X/Y`、OSM 标签、DOM 标识和着色器属性属于数据或接口约定，不随局部变量重命名。修改这些约定时，需要一起核对发送端、接收端、模型素材和着色器。

## 几何与状态约定

1. 地理输入是经纬度；几何在瓦片锚点附近转换为米制坐标，`MapScene` 再转换到地图使用的 Mercator 坐标。平面方向与海拔的缩放分开处理，不要把像素、米和地图单位混用。
2. 多边形保留闭环端点，外环逆时针、孔洞顺时针。裁剪和直骨架对环方向有要求。
3. 缺少的建筑高度、道路宽度和树木尺寸沿用确定性推断，并保留推断标志。重载同一数据时应保持稳定。
4. 建筑三角形范围和顶点范围与索引缓冲区配套，裁剪或打包后需要同步更新，否则建筑拾取会指向错误对象。
5. Worker 通过 transfer list 转移缓冲区所有权；转移后的发送端缓冲区不可继续使用。数据字段名需与调度器和渲染器保持一致。
6. MapLibre 与 Three.js 共用 WebGL 上下文；切换渲染器时必须维持现有深度、视口和状态恢复顺序。
7. 瓦片请求带版本和取消信号，移动地图后应丢弃过期结果；缓存淘汰需同时计入数量与内存预算。
